# Professional timeline and animation editing

Research and implementation audit: 2026-09-21. This document separates documented product behavior, MpVFX design decisions, and verified implementation. A capability listed here is not automatically a shipped feature.

## Findings from primary sources

There is no single standard covering every editor's shortcuts, magnetic timeline, overwrite policy, or effect model. The reliable common ground is non-destructive media editing, explicit animation ownership, consistent time conversion, and reversible commands. An editing operation must preserve the picture and sound unless changing them is its purpose.

## MpVFX edit contract

These are implementation decisions informed by the sources, not claims that all products behave identically.

- Use integer output frames and rational frame rates. Clip ranges are half-open: `[start, end)`. A split at `F` assigns `F` to the right child; no frame is repeated or dropped.
- Store authored parameter keys in clip-local time, including negative times and times beyond the visible Out point. Such keys are animation handles, not invalid data. Evaluate the complete curve before applying visibility.
- Splitting retains every key, value, interpolation and parameter on both independent children. The right child's local key times subtract the cut offset. Moving either child then carries its own animation.
- Trimming In shifts local key times by the trim delta; trimming Out changes only duration. Extending an edge restores the original curve. No destructive curve fitting or dense frame baking is needed.
- Image, title and graphic duration is independent of media availability. Audio/video source handles are finite. Native image splits must not advance the source offset as if the image were moving footage.
- Copy must capture authored state, never the rendered DOM at the current playhead. Duplicate/paste receives fresh clip, binding, effect and parameter-track identities, while retaining asset references. Mutating a copy must not mutate its source.
- Multi-clip paste preserves relative start times and track relationships. The earliest clip anchors to the captured playhead. Keyframe paste similarly preserves relative time and easing, but requires compatible parameter types and owners.
- Selected-key deletion affects only those keys. Removing all animation holds the evaluated value at the invoked frame. Resetting the parameter to its default is a separate operation.
- Commands capture project, selection, frame and mode when invoked. One logical action creates one atomic save and one undo entry, including mixed files. A failed operation changes nothing.
- Keyboard scope follows the active editor: text editing first, then a keyframe/automation selection, then clips. Select All must not unexpectedly switch from keys to clips. Copy failure must never enable destructive Cut.
- Snapping and collision rules must be explicit. Move a key selection with one delta to retain spacing. Do not merge unrelated properties or silently overwrite an occupied key.

The initial implementation has native media clips plus compatibility HTML/GSAP and a separate audio automation model. Their behavior must be audited separately; native tests alone cannot prove titles, effects or audio envelopes.

## Verification policy

Add failing behavioral tests before changing semantics. Compare every visible frame before and after a neutral split; test trim → save → reopen → extend against the original authored keys. Exercise non-linear and hold segments, rational fps, multi-property and non-video data. Verify UI commands, keyboard ownership, persisted identities, failure rollback, and exported output. Keep future capabilities and unsupported legacy cases explicit until they pass their own checks.

## Implementation delivered in this branch

### Preserve the authored animation, including handles

Native keyframe frames are signed safe integers. Both split children retain the complete curve, including cubic Bezier control points and Hold interpolation. Trim In changes the local origin; Trim Out changes visibility. Lanes hide out-of-range diamonds while the evaluator still uses those keys. Editing the outgoing interpolation on the last visible key remains possible when its next key is hidden. Still-image cuts leave the source offset unchanged.

For a clip starting at project frame `S`, cut at `F`, with an authored key at local frame `K`, the left key stays at `K` and the right key moves to `K - (F - S)`. For example, keys at 0 and 90, cut at local frame 45, become `[0, 90]` on the left and `[-45, 45]` on the right. Both children reproduce the original picture at every retained frame. A later move changes the child's sequence start, not those relative key times. Trimming In by 15 frames subtracts 15 from every local key; extending it back adds 15 again.

This removes destructive curve clipping and endpoint approximation. Native regression coverage includes all fourteen exposed scalar visual channels, number/vector/color storage, rational 30000/1001 frame rates, overshooting Beziers, Hold, repeated cuts and trim/save/reopen/extend. Generic audio/effect parameter IDs also exercise the storage model; those model tests do **not** establish a native audio/effect UI or rendering implementation.

Audio uses its existing seconds-based volume/effect envelope schema. Split retains every point on both children and rebases the right envelope; Trim In shifts the full envelope. The editor, preview runtime and producer normalizers are patched together so negative times survive serialization and export preparation. The patch validates the supported dependency shape and the original or already-patched runtime checksum before refreshing the producer integrity manifest. Packaging rejects an absent patch or stale checksum; runtime integrity checks stay enabled. Existing authored point limits remain unchanged. Ordinary audio and visual trimming no longer invokes the legacy animation-stretch operation.

### Independent copies and explicit command scope

Clip Copy, Cut, Paste and Duplicate capture saved authoring data, including native animation, static values, effects, inline styles, title content, audio attributes and supported GSAP animation. They allocate fresh clip/binding/descendant/effect/parameter/key identities. Multiple clips keep their relative start times and authored tracks. Paste anchors the earliest clip to the invoked playhead; Duplicate places the selected group after its end. Copy and paste currently stay within the same project and open composition.

Legacy selector-based animations are retargeted to copied elements. Shared class selectors are fixed to their original targets before adding copies, preventing a new instance from being animated by both its own tween and the source tween. Splitting uses the same authored-data path and retains the original project-time curves. Mixed native-media and title/graphic split or delete commits the HTML and native sidecar in one transaction.

The native keyframe clipboard preserves selected values, outgoing interpolation and relative project-frame spacing. It supports grouped lanes such as X/Y position. Paste requires matching frame rate and value types, a compatible clip, and an unoccupied destination key time. The first pasted key anchors inside the destination clip; later keys may extend beyond Out. A rejected keyframe command never falls through to clip paste. These choices are explicit MpVFX policies; other editors may offer an overwrite or frame-rate-conversion option.

Cmd/Ctrl+C, X, V and D and clip/keyframe context menus use these paths. Cmd/Ctrl+A respects a selected-key scope, otherwise selecting unlocked timeline clips. Composition roots are excluded. Select All and newly pasted selections clear stale canvas selection and explicitly retain timeline command ownership across delayed canvas mirrors, so offscreen timeline clips are included by Delete. A genuine new canvas selection takes ownership back. Text inputs and the existing audio-automation editor retain keyboard ownership. A complete panel-focus model remains future work.

Undo waits for queued file edits to finish before choosing its history entry. This fixes an observed Cut/Undo race where a file was saved but its history record had not yet become available. Clipboard, split and delete failures do not leave a partially committed native/HTML document.

### Evidence and limits

- Focused model, persistence, clipboard, trim, audio, selection and transaction regressions pass. The local native Electron workflow passes sixteen checks, including actual canvas gestures, keyframe paste/delete/undo, clip copy/cut/duplicate, split/reopen, Select All/Delete All, and atomic undo.
- The export-script test evaluates every visible frame using hidden eased keys and compares the emitted style to preview. Audio tests compare envelope samples before/after repeated cuts and validate all 21 patched normalization sites, including embedded preview/offline FX runtimes and PCM/FFmpeg volume adapters. A separate packaged Apple Silicon check at revision `29b21f6` rendered an eased volume envelope before/after a 0.5-second cut using a lossless source and H.264/AAC output: all measured 25 ms decoded-audio RMS windows matched. At revision `89f2d3f`, standalone-audio renders measured a maximum 0.81% window difference for a linear volume envelope and 1.65% for an eased gain-effect parameter; both retained the intended rising envelope. These are 25 ms decoded-audio RMS comparisons, not sample-exact assertions. An earlier AAC-source comparison showed a maximum 3.1% window difference. Stateful audio-effect pre-roll/tails, listening tests and broader codec coverage remain separate acceptance work.
- Typecheck and the production desktop build pass. The full local suite has 578 passing suites and 6,833 passing tests, with seven failing suites (six assertion failures plus two fixture-loading errors). The same failures were observed before this work: deleted composition-reliability/design-panel-qa fixtures, decorative-style policy, media import, property-panel coverage and track persistence. These are recorded limitations, not a green full-suite claim. The user's intentionally removed publication files and fixtures are not restored or made mandatory by this work.
- Cross-platform evidence is produced by the native-verification workflow for macOS arm64/x64, Windows x64 and Linux x64. Hosted runners use generated media; they do not establish behavior on every customer's GPU, device or real project. The PR records the current revision's run and outcome.
- Saved negative or beyond-Out keys require this updated reader. Earlier builds that enforced visible-range-only keyframes may reject a newly edited project. Keep a project copy when comparing older builds.

## Remaining professional-editing work, in priority order

| Priority | Capability | Contract and proof required before calling it complete |
| --- | --- | --- |
| 1 | Universal animation ownership | Give visual effects, title properties, audio effects and nested compositions the same typed owner/time-domain registry. Clip, source and track automation must remain distinct. Expose only parameters the evaluator and export renderer support. |
| 1 | Attribute and keyframe paste | Add a parameter picker, Maintain Timing / Stretch to Fit, explicit replace/merge collision policy and rational-fps conversion preview. Independent legacy visual-keyframe paste and cross-project media transfer remain unsupported. |
| 1 | Ripple, roll, slip and slide | Implement separate commands with source-availability checks, track locks, sync locks, linked A/V participation, gap/overwrite policies and one atomic multi-track undo. Do not repurpose ordinary trim as rate stretch. |
| 1 | Focus and selection | Track active panel and owner explicitly even with zero selected keys. Add select-to-playhead/range, invert, marquee and keyboard navigation with one shared command availability layer. Locked items and nested scopes must behave consistently. |
| 2 | Retime | Model variable/reverse speed as a source-time mapping. Define whether animation follows clip time or source time, plus pitch policy, frame interpolation and source-handle validation. Prove preview/export equivalence at boundaries. |
| 2 | Compound clips, nests and linked A/V | Carry local-to-parent rational time mappings, stable bindings and explicit link/group identities. Moving, splitting or rippling a group must preserve sync without flattening its independent parameters. |
| 2 | Transitions and effects | Evaluate required overlap handles and reject insufficient source media before writing. Keep independent effect instances separate from shared source effects. Cover stacked effects, masks, adjustment layers and disabled effects. |
| 2 | Curves and precision editing | Numeric time/value entry, multiple-key relative movement, snapping modes, tangent editing, interpolation presets, fit-to-selection and visible access to hidden handles. Reuse the same evaluation function in preview, inspector and export. |
| 3 | Scale and interchange | Stress-test long timelines and large selections, virtualize keyframe displays, use stable command transactions, and define loss reports for OTIO/XML/AAF interchange rather than silently dropping unsupported effects. |

The compatibility clipboard handles inline static GSAP calls and inline CSS. Dynamic expressions, unsupported timeline positions, partial selection of a shared multi-target animation, and unstable parent identities are rejected when detected. Arbitrary external animation scripts, linked ID-specific stylesheets and procedural dependencies are not a proven transfer format; they need dependency-aware materialization or conversion before broad compatibility is claimed. Moving a legacy tween earlier than composition time zero is also rejected. Generated media clips and the tested title/graphic forms do not establish universal HTML-document editing.

## How the system can improve itself reliably

Maintain an operation × media/parameter owner × time-domain matrix as executable acceptance scenarios. A neutral operation should preserve rendered frames and audio samples; an intentional change should alter only its declared targets. Every bug report should produce a small, versioned project fixture and a user-level action sequence, with generated substitutes for private media wherever possible.

For diagnostics, record bounded command metadata such as operation type, parameter category, clip count, frame rate, before/after revision, transaction outcome, duration, and a stable error code. Do not upload source HTML, media, title text, file paths or arbitrary project values as routine telemetry. Correlate edit failures and undo failures with app revision and platform, then turn reproducible failures into matrix cases. Screenshot artifacts remain restricted to disposable generated-media CI projects with the existing privacy gate.

Require three kinds of evidence for a new command: pure time/curve tests, persisted project/undo tests, and a native UI scenario. Add rendered frame comparisons and audio-envelope/waveform checks where picture or sound can change. A build's evidence must name its commit and distinguish source-app, installer, hosted-runner and physical-device checks. This makes gaps visible and prevents a successful size-control test from being mistaken for support for the entire keyframing system.
