## Findings and repair plan

1. **Linux MOV encoding fails in the tested custom-resolution export.** The
   report reaches the disk-backed PNG image-sequence path and FFmpeg rejects it
   because its PNG decoder is absent. The existing raw-frame patch covers the
   streaming encoder, leaving this path uncovered. Repair the disk-backed path
   or supply an audited binary with the required decoder. Verify both paths,
   including custom dimensions and more than one capture worker.

2. **Small-window export controls are clipped.** With custom dimensions open
   on the 1024×768 Windows and Apple Silicon desktops, settings consume the
   render panel and the job list/Cancel control falls outside the usable area.
   The attempted cancellation completed normally instead. Cancellation succeeds
   in the larger Intel Mac and Linux layouts. Repair panel scrolling and minimum
   sizing; verify Cancel is actually hit-testable and sends a cancellation
   request at the supported minimum window size. Backend cancellation failure
   has not been established by the clipped-control case.

3. **Windows installation is unfinished as a user experience.** Setup exits
   successfully and installs the application, but no MpVFX shortcut was found
   in user or shared Desktop/Start Menu locations. The green animation matches
   `electron-winstaller/resources/install-spinner.gif`; the Forge configuration
   supplies no application icon, setup icon, or custom loading animation. Add
   Squirrel lifecycle/shortcut handling and consistent MpVFX installer branding.
   Verify install, shortcut launch, update, and uninstall from the desktop.

4. **Completed MOV thumbnails look broken.** The Intel Mac render queue shows
   a broken-image placeholder for a successful MOV whose decoded output pixels
   are correct. Repair thumbnail generation/fallback for ProRes without relying
   solely on Chromium's ability to play that codec. This is distinct from the
   Linux encoding failure.

The diagnostics disclosure also crowds the asset area in the small-window
captures. Include that state in the layout repair.

## Limits and privacy

- These are hosted machines. Physical GPUs, Windows 11 SmartScreen, signing
  prompts, varied DPI scaling, long real projects, RPM installation on Fedora,
  and the original user's exact crash were not validated.
- File choice was supplied through the test driver after pressing Import media;
  the native file-picker UI was not exercised.
- Native crash dialogs were visually inspected; recovery used process restart.
  The dialog's Save and Reload buttons were not clicked by this test. Report
  saving through the editor's diagnostic control was exercised on all targets.
- The 1024×640 screenshot is a viewport-emulation check, separate from the real
  native desktop screenshots. It is not proof of native window-resize behavior.
- The Windows movie samples approximately one frame per second; exact timing
  belongs to the window inventory. It is not a full-frame-rate recording.
- Only generated test media and disposable runner profiles were used. No user
  projects, desktop content, Keychain credentials, native memory dumps, or raw
  diagnostic archives are included in the visual artifacts.

The overall workflow remains red for the recorded release failures. The Intel
Mac automated journey passed, but its MOV thumbnail still failed visual review.
